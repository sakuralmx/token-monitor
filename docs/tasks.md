## 任务明细

### T1 固化阿里云 Hub 部署
- 描述：将阿里云 ECS 上的 Node Hub 部署固化为可重复流程：systemd 服务单元（Hub 仅监听 `127.0.0.1:17321`）、独立 HTTPS 反向代理（443 → 回环 17321）、Let's Encrypt IP 证书由 Certbot 自动续期（含 dry-run 与到期监控、部署钩子）、健康检查、升级、回滚与备份步骤。仓库只记录部署模板与流程文档，不提交服务器秘密、证书私钥与部署凭据。
- 依赖：无
- 验收标准：提供可重复的 systemd、HTTPS 代理、Certbot 续期、健康检查、升级、回滚和备份说明；Hub 仅监听回环地址；服务器重启后自动恢复；不依赖域名、Cloudflare 或 Tailscale。

### T2 完成客户端公网 Hub 配置体验
- 描述：客户端 GUI 支持保存 HTTPS IP Hub URL 与共享密钥；连接测试能区分网络、证书、认证与 Hub 版本错误并给出可读提示；启动 Token Monitor 后自动采集、上传并接收 SSE，HTTP 回退机制沿用现有实现；退出后不遗留额外 VPN/Tailscale 服务。
- 依赖：T1（需真实部署的 Hub 验证）
- 验收标准：GUI 可保存 HTTPS IP Hub URL 和共享密钥；连接测试能区分网络、证书、认证和 Hub 版本错误；启动 Token Monitor 后自动采集、上传并接收 SSE；退出后不遗留额外 VPN 服务。

### T3 定义会话目录兼容协议
- 描述：在 `docs/API.md` 中新增版本化的会话目录协议：批量 upsert、增量读取/分页、删除或失效语义、负载限制、错误码；明确旧 Hub/旧客户端组合的降级行为；不得破坏原有设备记录线协议（`docs/API.md` 现有契约）。
- 依赖：无
- 验收标准：在 `docs/API.md` 记录版本化的批量 upsert、增量读取/分页、删除或失效语义、负载限制和错误码；旧 Hub/旧客户端组合有明确降级行为；原有设备记录线协议不被破坏。

### T4 实现本地隐私清洗与统一模型
- 描述：实现统一 `SessionCatalogEntry`（主键 `deviceId + client + sessionId`，含稳定会话 ID、客户端类型、脱敏工作区键、工作区显示名、标题、首次/最后活动时间、消息数及可选统计摘要）；标题回退取第一条有效用户消息并本地截断与清洗，禁止 AI 生成标题；工作区只同步稳定哈希/规范化项目键与安全显示名；配套隐私回归测试。
- 依赖：T3（统一模型与字段定义来自协议）
- 验收标准：绝对路径、用户名、正文、凭据不会出现在网络载荷；标题长度、空白、控制字符和异常编码被统一处理；稳定键在同一项目跨重启不漂移；覆盖隐私回归测试。

### T5 恢复 Cherry Studio 会话适配
- 描述：实现 Cherry Studio 本地适配器（与 T4 统一模型对接）：显示会话所属工作区与已有标题；缺失标题时用首条有效用户消息回退；兼容当前及已知旧版存储结构；解析失败按文件/会话隔离，不中断用量采集。
- 依赖：T4
- 验收标准：能显示会话所属工作区和已有标题；缺失标题时使用首条有效用户消息；兼容当前及已知旧版存储结构；单条损坏记录不影响其他会话。

### T6 增加 Codex 会话适配
- 描述：实现 Codex 本地适配器：从本地 Codex 会话数据提取稳定会话 ID、工作区、标题回退与时间信息；Windows、macOS、Linux/WSL 路径均有 fixture 测试；不上传原始 JSONL 内容。
- 依赖：T5（与 T5、T7 串行实现）
- 验收标准：从本地 Codex 会话数据提取稳定会话 ID、工作区、标题回退和时间信息；Windows、macOS、Linux/WSL 路径均有 fixture 测试；不上传原始 JSONL 内容。

### T7 增加 DSH 会话适配
- 描述：实现 DSH 本地适配器：支持 DSH 的压缩会话文件与可用元数据；zstd 能力采用特性检测，不支持时给出清晰状态；解析资源有大小/时间边界；不影响用量采集。
- 依赖：T6（与 T5、T6 串行实现）
- 验收标准：支持 DSH 的压缩会话文件和可用元数据；zstd 能力采用特性检测并有不支持时的清晰状态；解析资源有大小/时间边界；不影响用量采集。

### T8 实现 Hub SQLite 永久目录
- 描述：Hub 侧以 SQLite 实现永久会话目录：优先评估 Node 24 内置 `node:sqlite`（先用项目最低 Node、部署 Node 24 与 Electron runtime 验证，能力不足再单独讨论依赖方案，不擅自新增依赖）；重复上传幂等、并发写入不丢数据；schema 版本、迁移、备份与恢复测试；共享密钥保护所有目录接口；建索引并分页读取。
- 依赖：T3（目录接口与负载限制来自协议）
- 验收标准：重复上传幂等；并发写入不丢数据；设备离线和 Hub 重启后记录仍存在；具有 schema 版本、迁移、备份与恢复测试；共享密钥保护所有目录接口。

### T9 实现增量同步和冲突规则
- 描述：客户端只上传变化项；相同会话按字段来源优先级与 `updatedAt` 合并，旧设备迟到数据不能覆盖较新标题；断网重试不制造重复记录；批次受限并可续传。
- 依赖：T8（需 SQLite 存储层承载）
- 验收标准：客户端只上传变化项；相同会话按字段来源优先级和 `updatedAt` 合并；旧设备迟到数据不能覆盖较新标题；断网重试不会制造重复记录；批次受限并可续传。

### T10 实现按工作区分组的会话 UI
- 描述：展示层按工作区分组（组内按最后活动时间倒序），支持“全部会话”与客户端筛选、折叠与数量显示；排序、筛选、空态、加载态、离线缓存与长标题布局；设置页明确说明同步内容并提供关闭会话元数据同步的开关；总量来自永久目录，今日/月度沿用现有周期窗口计算；不恢复显示任何原始正文。
- 依赖：T5、T6、T7、T9
- 验收标准：Cherry Studio、Codex、DSH 会话可统一浏览；分组可折叠并显示数量；排序、筛选、空态、加载态、离线缓存和长标题布局均正确；不恢复显示任何原始正文。

### T11 端到端与运维验收
- 描述：两设备错峰上线互看统计与会话元数据；关闭 VPN/Tailscale 后仍可同步；证书校验、SSE 断线恢复、Hub 备份恢复演练；抓包与 Hub 数据检查确认无原始正文/凭据/本地绝对路径；`npm run verify` 全部通过并完成 UI 截图检查。
- 依赖：T2、T10（全部实现完成后）
- 验收标准：两台设备错峰上线可相互看到统计和会话元数据；关闭 VPN/Tailscale 后仍可同步；证书校验正常；SSE 断线可恢复；Hub 备份恢复成功；`npm run verify` 全部通过并完成 UI 截图检查。

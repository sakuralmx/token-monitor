# Token Monitor 个人多设备同步与会话目录规划

> 本文件是当前功能目标的长期规划。实现阶段必须继续遵守 `AGENTS.md` 的兼容性、生成文件和验证约定。

## 目标

1. 仅运行 Token Monitor 客户端即可让多台不会同时在线的个人设备汇总数据；中转端使用阿里云 Node Hub，不要求域名、Cloudflare 或 Tailscale。
2. 恢复 Cherry Studio 会话的工作区与简要标题，并以同一套数据模型支持 Codex 和 DSH。
3. 只同步统计数据和安全的会话元数据，不上传原始会话正文、提示词、回答、凭据或本地绝对路径。
4. 会话目录永久保留；设备离线、重装或历史日志轮转后，已同步的会话标题与工作区仍可查询。

## 当前迭代：合并会话目录展示

### 目标

- 删除视图切换器中的独立“目录”入口，不删除会话元数据采集、同步、缓存或设置。
- 将目录标题和工作间信息合并到“会话”视图，避免两套会话入口表达同一批数据。
- 每个会话按以下层级显示：工作间名称 Tab、醒目的会话名称、工具与模型 / Token 数、时间与消息数量 / 价格；不显示会话 ID。

### 任务与验收标准

- [x] UI1 移除独立目录视图
  - 验收标准：视图菜单不再出现“目录”；旧的持久化 `catalog` 视图值安全回退到“会话”；页面不再保留目录专用面板与样式。
- [x] UI2 重构会话数据模型
  - 验收标准：会话行能从 Catalog 元数据取得标题和工作间名，并稳定提供工具、模型、Token、时间、消息数量和价格；无 Catalog 匹配时有清晰回退，不展示原始 ID。
- [x] UI3 实现会话卡片布局
  - 验收标准：工作间以紧凑 Tab 形式置顶；会话名称视觉突出；两行辅助信息按需求排列；长文本、省略、窄窗口和缺失字段不破坏布局。
- [x] UI4 自审、验证与交付
  - 验收标准：补齐模型与 DOM/CSS 回归测试；执行 `npm run verify`；完成 UI 代码自审；通过后运行 Windows 打包、产物命名验证、静默安装并确认安装版本/进程。

### 风险点

- Catalog 包含跨设备的永久会话，而用量视图只包含当前周期中有统计的会话；本轮以“会话用量行为主、Catalog 元数据增强”为准，不凭空为无用量会话伪造 Token 或价格。
- 旧设置可能保存 `breakdown: catalog`；移除枚举时必须显式迁移到 `session`，避免启动后意外回到首页。
- 工作间、模型或标题可能缺失；展示层必须使用本地化回退文本，并且不能退回显示会话 ID。

## 当前迭代：有界会话加载与跨设备统一展示

### 目标

- 打开“会话”视图时不再分页拉取全部永久历史，只读取最近一页，避免大量网络、JSON 与重复渲染开销。
- 其他设备同步到 Hub、但当前设备用量周期中没有对应行的会话，也使用与本机会话相同的卡片结构显示。

### 任务与验收标准

- [ ] PERF1 限制 Catalog 首屏读取
  - 验收标准：Hub 首屏只请求一次、最多返回最近 200 条；结果携带 `hasMore`，不在后台自动追完游标；本地回退也只向渲染器返回最近 200 条。
- [ ] PERF2 合并远端会话卡片
  - 验收标准：Catalog-only 会话按 `deviceId + client + sessionId` 保持设备隔离；与已有用量行去重；工作间、标题、工具/未知模型、Token、时间、消息数、价格使用相同结构；显示集合严格服从右上角 DAY / WEEK / 7D / MONTH / 30D / TOTAL 时间筛选。
- [ ] PERF3 回归与性能验收
  - 验收标准：覆盖单页网络请求、200 条上限、跨设备同 ID 不误合并、已有用量行不重复；聚焦测试和 `npm run verify` 达到项目当前 Windows 基线。

### 性能边界

- 本轮先实现确定性的 200 条最近会话窗口，不自动加载更早历史；后续若需要完整历史浏览，应增加用户触发的“加载更多”或搜索，而不是恢复全量预取。
- 200 条是网络和渲染上限，不是绕过时间筛选的固定列表；会话先按右上角范围过滤，再按最后活动时间倒序显示。
- Catalog 协议没有模型字段；远端 Catalog-only 卡片以工具名加未知模型占位显示，不猜测模型。Token 与价格仅使用 Catalog 已同步的可选 `stats` 摘要。

## 已确定方案

### 多设备中转

- 阿里云 ECS 常驻 Node Hub，客户端地址为裸公网 IP 的 HTTPS URL。
- Let's Encrypt IP 证书由 Certbot 自动续期；独立 HTTPS 反向代理把 443 转发到仅监听 `127.0.0.1:17321` 的 Hub。
- 客户端仍使用现有共享密钥认证、SSE 更新和 HTTP 回退机制。每台设备只需启动 Token Monitor；无需 VPN、Tailscale 或额外客户端。
- Hub 保存设备最新记录和中心化会话目录，因此设备不必同时在线：A 上传后关机，B 稍后上线仍可读取 A 的数据。
- 服务器秘密、证书私钥和实际部署凭据不进入 Git；仓库只记录部署模板、升级与备份步骤。

### 会话目录

- 新增统一 `SessionCatalogEntry`，主键为 `deviceId + client + sessionId`，至少包含：稳定会话 ID、客户端类型、脱敏工作区键、工作区显示名、标题、首次/最后活动时间、消息数及可选统计摘要。
- 标题优先采用客户端已有的本地标题；没有时取第一条有效用户消息并做本地截断与清洗。禁止调用 AI 生成标题。
- 工作区仅同步稳定哈希/规范化项目键和安全显示名；不得同步用户名、主目录或本地绝对路径。
- Cherry Studio、Codex、DSH 分别实现本地适配器，输出统一模型。解析失败必须按文件/会话隔离，不能中断用量采集。
- Hub 的永久会话目录使用 SQLite。优先评估 Node 24 内置 `node:sqlite`，避免给 Electron 主程序增加原生依赖；若兼容性验证不满足，再单独讨论依赖方案，不在实现时擅自新增依赖。
- 展示层按工作区分组，工作区内按最后活动时间倒序；保留“全部会话”和客户端筛选。总量来自永久目录，今日/月度使用现有周期窗口计算。

## 任务清单

- [ ] T1 固化阿里云 Hub 部署
  - 验收标准：提供可重复的 systemd、HTTPS 代理、Certbot 续期、健康检查、升级、回滚和备份说明；Hub 仅监听回环地址；服务器重启后自动恢复；不依赖域名、Cloudflare 或 Tailscale。
- [ ] T2 完成客户端公网 Hub 配置体验
  - 验收标准：GUI 可保存 HTTPS IP Hub URL 和共享密钥；连接测试能区分网络、证书、认证和 Hub 版本错误；启动 Token Monitor 后自动采集、上传并接收 SSE；退出后不遗留额外 VPN 服务。
- [ ] T3 定义会话目录兼容协议
  - 验收标准：在 `docs/API.md` 记录版本化的批量 upsert、增量读取/分页、删除或失效语义、负载限制和错误码；旧 Hub/旧客户端组合有明确降级行为；原有设备记录线协议不被破坏。
- [ ] T4 实现本地隐私清洗与统一模型
  - 验收标准：绝对路径、用户名、正文、凭据不会出现在网络载荷；标题长度、空白、控制字符和异常编码被统一处理；稳定键在同一项目跨重启不漂移；覆盖隐私回归测试。
- [ ] T5 恢复 Cherry Studio 会话适配
  - 验收标准：能显示会话所属工作区和已有标题；缺失标题时使用首条有效用户消息；兼容当前及已知旧版存储结构；单条损坏记录不影响其他会话。
- [ ] T6 增加 Codex 会话适配
  - 验收标准：从本地 Codex 会话数据提取稳定会话 ID、工作区、标题回退和时间信息；Windows、macOS、Linux/WSL 路径均有 fixture 测试；不上传原始 JSONL 内容。
- [ ] T7 增加 DSH 会话适配
  - 验收标准：支持 DSH 的压缩会话文件和可用元数据；zstd 能力采用特性检测并有不支持时的清晰状态；解析资源有大小/时间边界；不影响用量采集。
- [ ] T8 实现 Hub SQLite 永久目录
  - 验收标准：重复上传幂等；并发写入不丢数据；设备离线和 Hub 重启后记录仍存在；具有 schema 版本、迁移、备份与恢复测试；共享密钥保护所有目录接口。
- [ ] T9 实现增量同步和冲突规则
  - 验收标准：客户端只上传变化项；相同会话按字段来源优先级和 `updatedAt` 合并；旧设备迟到数据不能覆盖较新标题；断网重试不会制造重复记录；批次受限并可续传。
- [ ] T10 实现按工作区分组的会话 UI
  - 验收标准：Cherry Studio、Codex、DSH 会话可统一浏览；分组可折叠并显示数量；排序、筛选、空态、加载态、离线缓存和长标题布局均正确；不恢复显示任何原始正文。
- [ ] T11 端到端与运维验收
  - 验收标准：两台设备错峰上线可相互看到统计和会话元数据；关闭 VPN/Tailscale 后仍可同步；证书校验正常；SSE 断线可恢复；Hub 备份恢复成功；`npm run verify` 全部通过并完成 UI 截图检查。

## 实施顺序

`T1 → T2 → T3 → T4 → (T5、T6、T7 串行实现) → T8 → T9 → T10 → T11`

先锁定协议与隐私边界，再接入永久存储和 UI。按照个人工作流，同一时间只允许一个工具修改代码；每个任务独立提交，提交信息包含任务 ID。

## 风险点与对策

- **裸 IP 证书有效期短**：依赖自动续期计时器和部署钩子；增加续期 dry-run 与到期监控，备份证书配置但不备份私钥到仓库。
- **公网暴露面**：17321 不对公网监听，只开放 443；共享密钥必须高熵并支持轮换；限制请求体、请求频率和日志中的敏感字段。
- **阿里云单点故障**：定期备份设备 JSON、订阅文档和 SQLite 到服务器外；文档化恢复时间目标和全新主机恢复流程。
- **各客户端格式变化**：适配器隔离、fixture 版本化、未知字段容忍、解析失败可观察；不要让会话功能拖垮核心统计。
- **“标题”泄露正文**：回退标题只在本地生成，严格截断和清洗；设置页明确说明同步内容，并提供关闭会话元数据同步的开关。
- **永久保留导致增长**：SQLite 建索引并分页读取；保留导出、按设备/工作区清理能力，但默认不自动删除。
- **Node 版本差异**：在编码前用项目最低 Node、部署 Node 24 和 Electron runtime 验证 `node:sqlite`/zstd；能力不足时采用隔离于 Electron 的 Hub 方案。

## 最终验收定义

在所有设备均未安装或运行 Tailscale、Cloudflare 客户端及其他同步软件的情况下，仅启动 Token Monitor：设备能通过受信任 HTTPS 把统计和安全会话元数据写入阿里云 Hub；另一台稍后上线的设备能读取聚合统计，并按工作区查看 Cherry Studio、Codex、DSH 的永久会话标题目录。任何抓包和 Hub 数据检查均不得发现原始会话正文、凭据或本地绝对路径。
